# Early Informatics acceptance and pilot

## Current boundary

The application is ready for **synthetic local review**, not a completed operational/student pilot. No student interviews, adoption measurements, learning improvement or live-provider performance results were collected. Follow RELEASE-GATES.md before inviting real students.

## Synthetic review script

1. Start a fresh demo workspace as in the README. Sign in as `student@demo.school.test` with the password printed by the explicit demo command. Switch English/Russian from login or the sidebar; retain the original account system.
2. Open **My Training / Моя подготовка**. Create a goal/cycle, add an HTTPS external problem link, record an attempted/revisit outcome and optional assistance, reflection and next step. Close/reopen the plan; carry a selected unfinished item to a new private cycle. Export only your own training data. Codeforces account linking is not a prerequisite.
3. Create a **Training Circle / Группа самоподготовки**. On a second synthetic account request to join; approve as the local facilitator. Schedule an individual-practice cycle with a debrief gate. Confirm there is no freeform peer posting before the gate, including logistics. After the gate, post a selected explanation; private notes do not become shared automatically. Try leave/remove/consenting transfer and report/hide/lock with the appropriate actor.
4. Open the **Competitive Programming Hub**. During an external outage, verify that manual training still works and cached/empty contest data are labeled honestly. Do not enter another real person's handle simply to fabricate an ownership demonstration. Provider fixture ratings/contests used by automated tests are synthetic and never appear in production routes.
5. During a separately authorized live smoke test, use a consenting tester's own Codeforces handle. Check metadata consent and separate default-off ranking consent. School administrator observes account control on the tester's own device, selects the evidence method and approves. The label must read School-approved. Test opt-in, withdrawal, handle change/reapproval, disconnect, unrated state and duplicate-approval rejection. Never request or share a password.
6. As Mathematics/Physics teacher/student, check existing assignments, drafts, uploads, group work, manual grading, hidden competition results and release. Revisit an uncertain submission receipt without issuing a new duplicate intent. A local dashboard screenshot is not sufficient evidence of this workflow.

To verify classroom-independent eligibility, use the administrator's **Subject participation** screen for a synthetic student with no Informatics classroom. The admin grants subject participation, not classroom/teacher privileges. Automated tests also cover this independence and cross-owner denial.

## Real pilot, only after gates

Proposed cohort: roughly 10–12 voluntary Informatics students across experience levels/languages, including students with no connected Codeforces account and a multi-subject participant. Proposed observation period: four weeks. These are planning targets, not enrolled participants.

Observe whether participants complete goal→practice→next-step cycles and return for a meaningful action, not merely visit a leaderboard. Ask about time spent logging, clarity of peer roles, and whether circles can be run without routine staff assistance. The blueprint's provisional thresholds (60% week-four meaningful return; half completing a cycle; median logging below five minutes/week) remain hypotheses to compare against an actual baseline, not promised educational outcomes.

Use transparent, minimal approved aggregate reporting; no covert surveillance, keystrokes, automated skill diagnosis or compulsory rating participation. Identify the adult moderation contact and backup custodian before collection. Fix serious privacy/usability issues before broad rollout. The pilot should precede later product polish, but may not bypass persistence, consent and restore protections.
